4.1

CSV

Simple tabular data

The plainest way to store a table — one line per row, values separated by commas, and a header row naming the columns.

id,name,age,salary 1,Rahul,25,40000 2,Priya,28,55000 3,Amit,30,60000
read_csv.py
import pandas as pd

df = pd.read_csv("customers.csv")

print(df)
4.2

Excel

Business reporting

The default format for anyone working outside engineering teams — finance, sales and operations share data almost exclusively as .xlsx workbooks.

read_excel.py
import pandas as pd

df = pd.read_excel("customers.xlsx")

print(df)
4.3

JSON

APIs / web applications

Almost every API on the internet responds in JSON. For a flat structure, pandas can read it directly.

read_json.py
import pandas as pd

df = pd.read_json("customers.json")

print(df)

Real-world JSON is rarely flat — records are usually nested one or two levels deep, as seen in Module 3. In that case, pd.json_normalize() flattens the nested keys into columns.

read_nested_json.py
import json
import pandas as pd

with open("customers.json", "r") as file:
    data = json.load(file)

df = pd.json_normalize(data["customers"])

print(df)
4.4

Parquet

Analytics / data engineering

Parquet is especially common in modern analytics and data-engineering environments, because it is column-oriented rather than row-oriented — it physically stores data by column, not by row.

Row-oriented (CSV)

idnameagesalary
1Rahul2540000
2Priya2855000
3Amit3060000

Stored one full row at a time. Fast for reading one record end-to-end, but reading only "salary" for every row still means scanning every column.

Column-oriented (Parquet)

idnameagesalary
1Rahul2540000
2Priya2855000
3Amit3060000

Stored one full column at a time. An analytics query like "average salary" reads only the salary column, skipping everything else — much faster at scale.

parquet_demo.py
df.to_parquet("customers.parquet")

new_df = pd.read_parquet("customers.parquet")

print(new_df)

TAKEAWAY

One library, most formats

Pandas currently supports reading and writing several common data sources and formats, including CSV, Excel, SQL, JSON and Parquet — the format changes, but the pattern (read_<format> in, to_<format> out) stays the same.

pd.read_csv / df.to_csv pd.read_excel / df.to_excel pd.read_json / df.to_json pd.read_parquet / df.to_parquet
