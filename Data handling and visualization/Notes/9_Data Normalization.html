CHAPTER 09

Data Normalization

The values in a dataset are correct, complete and the right type — but if one column lives in the tens and another in the hundred-thousands, most algorithms will quietly let the larger one dominate. Scaling levels that playing field.

9.1

Why scaling?

Take a single record: Age = 25, Salary = 50000. The numerical magnitude is wildly different — and some machine-learning algorithms are directly affected by that gap.

Age

Salary

On a shared scale, Age is invisible next to Salary. Any algorithm that measures distance between points (like k-NN or k-means) will treat Salary as almost the only feature that matters — not because it's more important, but because of its raw magnitude.

Scikit-learn documents Min-Max scaling as transforming features into a specified range — commonly [0, 1] — so every feature contributes on comparable terms.

9.2

Min-max normalization

Every value is rescaled based on where it falls between the column's minimum and maximum.

X_normalized = (X − X_min) / (X_max − X_min)
rescales every value into the range [0, 1]

Worked example — Values = 10, 20, 30, so min = 10 and max = 30:

For 20:
(20 − 10) / (30 − 10)
= 10 / 20
= 0.5

9.3

Manual implementation

The same formula applied directly to a pandas column, for both age and salary at once.

manual_normalize.py
import pandas as pd

df = pd.DataFrame({
    "age": [20, 30, 40, 50],
    "salary": [20000, 40000, 60000, 80000]
})

df["age_normalized"] = (
    (df["age"] - df["age"].min())
    / (df["age"].max() - df["age"].min())
)

df["salary_normalized"] = (
    (df["salary"] - df["salary"].min())
    / (df["salary"].max() - df["salary"].min())
)

print(df)

9.4

Using MinMaxScaler

The manual formula is worth understanding once — in practice, scikit-learn's MinMaxScaler does the same thing more safely and consistently across many columns.

install.sh
pip install scikit-learn
minmax_scaler.py
import pandas as pd
from sklearn.preprocessing import MinMaxScaler

df = pd.DataFrame({
    "age": [20, 30, 40, 50],
    "salary": [20000, 40000, 60000, 80000]
})

scaler = MinMaxScaler()

df[["age", "salary"]] = scaler.fit_transform(
    df[["age", "salary"]]
)

print(df)
9.5

Important industry practice

Once training and test sets exist, how the scaler is fit matters just as much as the formula itself.

Correct

scaler.fit_transform(X_train)
↓
scaler.transform(X_test)

Avoid — causes data leakage

scaler.fit_transform(X_test)

Why? Because the scaling parameters — the min and max — should be learned from training data only. Fitting on the test set lets information about the test data's range leak into the model before evaluation, making performance look better than it really is.

Scikit-learn's preprocessing documentation explicitly describes fitting transformations on training data and then applying that learned transformation to later, unseen data.

Rule to remember

Fit once, on training data. Transform everything else with what you learned — never re-fit on data the model shouldn't have seen yet.

This same fit-on-train, transform-on-test discipline applies to every preprocessing step that learns parameters from data — not just scaling, but imputation, encoding, and beyond.
