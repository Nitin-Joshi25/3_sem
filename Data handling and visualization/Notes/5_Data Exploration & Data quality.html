CHAPTER 05 · WHERE PREPROCESSING BEGINS

Data Exploration & Data Quality

Every preprocessing pipeline starts by asking one question: what's actually wrong with this data? Before cleaning anything, you have to see it — clearly, and in detail.

SETUP

A deliberately imperfect dataset

To practice on something realistic, we build a small customer table with the exact flaws you'll meet in real projects: a duplicated record, missing values, and inconsistent category casing.

build_dataset.py
import pandas as pd

data = {
    "customer_id": [1, 2, 3, 4, 5, 5],
    "name": ["Rahul", "Priya", "Amit", "Sneha", "Ravi", "Ravi"],
    "age": [25, 28, None, 32, 29, 29],
    "salary": [40000, 55000, 45000, None, 60000, 60000],
    "city": ["Delhi", "Delhi", "Mumbai", "Pune", "delhi", "delhi"]

5.1

Inspect the data

Before anything else, get oriented: how big is this table, what are its columns, and what type is each one?

df.head()

Shows the first 5 rows — a quick sanity check that the data loaded correctly.

df.tail()

Shows the last 5 rows — useful for spotting trailing junk rows or footers.

df.shape

Returns (rows, columns) — here, (6, 5).

df.columns

Lists every column name — the first place to catch typos or inconsistent naming.

df.dtypes

Confirms whether pandas inferred each column correctly — a numeric column showing as object is an early warning sign.

inspect.py
print(df.head())
print(df.tail())
print(df.shape)
print(df.columns)
print(df.dtypes)
$ python inspect.py (6, 5) Index(['customer_id', 'name', 'age', 'salary', 'city'], dtype='object') customer_id int64 name object age float64 salary float64 city object dtype: object

df.describe() summarizes every numeric column at once — count, mean, spread and range — in a single call.

Duplicate records

df.duplicated() returns a boolean series — True wherever a row is an exact repeat of an earlier one.

duplicates.py
print(df.duplicated())
$ python duplicates.py 0 False 1 False 2 False 3 False 4 False 5 True dtype: bool

Only row index 5 is flagged — the first occurrence of Ravi's record (index 4) is kept as the original, and the repeat is what's marked.

5.5

Unique values

Categorical columns hide a different kind of problem — the same real-world value spelled two different ways.

unique.py
print(df["city"].unique())
print(df["city"].value_counts())
$ python unique.py ['Delhi' 'Mumbai' 'Pune' 'delhi']
Delhi
2
delhi
2
Mumbai
1
Pune
1

unique() reports 4 distinct city labels — but "Delhi" and "delhi" are the same city. Without standardising case first, every count and group-by downstream silently splits one city into two.

MINDSET

Industry data quality checklist

Before touching a single cleaning function, a working data professional runs through these questions on every new dataset.

Are there duplicates?
Are values missing?
Are data types correct?
Are categories consistent?
Are there impossible values?
Are there outliers?
Are column names meaningful?
Are units consistent?
The core lesson of this module

This mindset is more important than memorizing pandas commands.

Commands change between libraries and languages. The habit of interrogating a dataset before trusting it does not — and it's what separates a script that "runs" from an analysis that's actually correct.
