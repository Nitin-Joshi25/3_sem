CHAPTER 03 · CORE INDUSTRY CONCEPT

Structured, Semi-Structured & Unstructured Data

Almost every data engineering decision — which database, which pipeline, which tooling — comes down to where a dataset sits on this spectrum. This is one of the most asked concepts in real-world interviews.

Structured — rigid rows & columns Semi-structured — tagged, nested Unstructured — no fixed shape
3.1

Structured data

Highly organized data that fits neatly into rows and columns, where every record shares the exact same fields.

PRACTICAL

Building structured and semi-structured data

The same session can produce a clean tabular DataFrame and a nested JSON file side by side — one script, two structural shapes.

structure_demo.py
import pandas as pd
import json

structured_data = {
    "id": [1, 2, 3],
    "name": ["Rahul", "Priya", "Amit"],
    "age": [25, 28, 30]
}

df = pd.DataFrame(structured_data)

print("Structured Data:")
print(df)

json_data = {
    "customers": [
        {"id": 1, "name": "Rahul", "age": 25},
        {"id": 2, "name": "Priya", "age": 28},
        {"id": 3, "name": "Amit", "age": 30}
    ]
}

with open("customers.json", "w") as file:
    json.dump(json_data, file, indent=4)

print("\nJSON file created.")
$ python structure_demo.py Structured Data: id name age 0 1 Rahul 25 1 2 Priya 28 2 3 Amit 30 JSON file created.

Import pandas and json

Two different libraries for two different shapes of data — pandas for tables, json for nested structures.

Build the structured table

Define a dictionary of equal-length lists and pass it to pd.DataFrame() to get rows and columns.

Print the DataFrame

Call print(df) to confirm the structured shape — every row has the same fields.

Build the nested JSON object

Define a Python dictionary containing a list of records — this is the semi-structured shape.

Write it to a file

Open customers.json in write mode and call json.dump(json_data, file, indent=4) to persist it with readable indentation.

Confirm the write

Print a confirmation message, then open customers.json to see the nested structure on disk.

TAKEAWAY

Why this distinction matters

One dataset, three structural levels:

The same real-world entity — a customer, a patient, a transaction — is rarely just one type. Recognising which parts are structured, semi-structured or unstructured decides which storage system, which parsing logic, and which model architecture can actually be used on it.

Structured → SQL, DataFrames Semi-structured → JSON/XML parsers, NoSQL Unstructured → files, ML/NLP/CV pipelines
